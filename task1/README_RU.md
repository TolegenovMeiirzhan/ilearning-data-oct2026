# №1 — самая длинная общая подстрока

Сдавать нужно только **lcs.js**, имя строго в нижнем регистре. Его размер — **138 байт**, это диапазон «good» в опубликованной шкале размера. Глобально минимальный размер не заявляется. Исходник нельзя оборачивать в `use strict`: короткая версия использует глобальные переменные.

```powershell
node lcs.js ABCDEFZ WBCDXYZ
node lcs.js ABC XYZ
node lcs.js
node test.mjs
```

Первая команда печатает `BCD`, вторая и третья — только перевод строки. Аргументы с пробелами или пустую строку передают в кавычках. Для объяснения есть `lcs-readable.js`, но его отправлять вместо короткого файла не нужно.

Алгоритм берёт первую строку. Проверяет все её подстроки начиная с максимальной длины. Для каждой `every` проверяет `includes` во всех аргументах. Как только подстрока есть везде, она печатается. Поскольку длина убывает, найденный ответ максимальный. При нескольких правильных ответах допускается любой. Подстрока непрерывная: переставлять буквы или пропускать символы нельзя.

В коротком коде `a` — аргументы, `s` — первая строка, `n` — проверяемая длина, `i` — начало, `t` — кандидат. `substr(i,n)` формирует кандидат. После перебора начал `n` уменьшается. Пустая строка входит в любую строку, поэтому поиск завершается и при отсутствии общих символов. `console.log` добавляет ровно один перевод строки.

Критерии: только `process.argv`; чистый Node.js; без импортов, зависимостей, чтения файлов, stdin и сети; никаких приглашений/отладки в stdout; корректный пустой ввод; ограничения до 64 строк по 256 символов не зашиты в решение. В худшем случае перебирается O(L²) кандидатов и до K поисков для каждого; допустимость времени проверяется реальными запусками, а не обещанием асимптотики.

`test.mjs`: 1017 сравнений с независимым перебором-эталоном и 17 запусков настоящего CLI, включая пустой ввод, неоднозначные ответы и предельные размеры. Проверяются максимальность ответа, stderr, перевод строки и ограничение 5 секунд на процесс.

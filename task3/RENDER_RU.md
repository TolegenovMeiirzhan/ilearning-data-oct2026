# Размещение ДЗ №3 в Render

Существующий сайт: https://scrm-3ezo.onrender.com/ . Один адрес не предоставляет доступа к настройкам или коду. ДЗ пока не опубликовано.

Для отдельного Python-сервиса в том же аккаунте Render:

1. Создай отдельный репозиторий GitHub и загрузи в его корень `app.py`, `Dockerfile`, `.dockerignore`, `render.yaml`. Не загружай ZIP как один файл.
2. В Render выбери **New → Blueprint**, подключи этот репозиторий. Файл render.yaml содержит настройки сервиса и регистрационный email. Перед созданием проверь выбранный план и доступность Free в своём аккаунте.
3. Альтернатива: **New → Web Service**, тот же репозиторий, runtime Docker, переменная REGISTRATION_EMAIL=`YOUR_REGISTRATION_EMAIL`. Приложение слушает 0.0.0.0 и PORT.
4. После успешного Deploy скопируй фактический URL из Render. Название сервиса в конфигурации не гарантирует точный выдаваемый поддомен.
5. Открой `https://ФАКТИЧЕСКИЙ-ДОМЕН/tolegenovmeiirzhan_gmail_com?x=12&y=18`: результат только `36`. Для `x=abc&y=18` — `NaN`, для `x=0&y=0` — `0`.
6. После проверки отправь боту одну строку, подставив фактический домен:

```text
!task3 YOUR_REGISTRATION_EMAIL https://ФАКТИЧЕСКИЙ-ДОМЕН/tolegenovmeiirzhan_gmail_com?x={}&y={}
```

Фигурные скобки оставь буквально. На бесплатном плане сервис может засыпать; открой тестовый URL перед сдачей и дождись ответа.

Чтобы использовать именно путь на scrm-3ezo.onrender.com, требуется изменение существующего приложения/прокси и проверка его конфигурации. Отдельный сервис получает собственный публичный адрес; этот адрес тоже удовлетворяет условию ДЗ.

Документация: https://render.com/docs/web-services , https://render.com/docs/blueprint-spec . Конфигурация подготовлена локально; деплой и проверка в аккаунте Render не выполнялись.

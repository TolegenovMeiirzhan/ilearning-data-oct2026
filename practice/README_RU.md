# Practice — XOR Linked List

[Условие и тесты преподавателя](https://discord.com/channels/950701840901746708/1558552677296906350/1558553123017064502): выбрать язык, реализовать XOR-связный список так, чтобы прошли тесты, и добавить свои. Выбран Python. Внешние библиотеки самому списку не нужны.

## Идея

В обычном двусвязном списке у узла две ссылки: на предыдущий и следующий. Здесь хранится их XOR: `link = previous ^ next`. При обходе предыдущий адрес известен, значит следующий находится как `next = previous ^ link`, поскольку `a ^ a = 0`.

Буфер состоит из 32-битных беззнаковых чисел; узел занимает **два** числа: значение и XOR адресов. Адрес — смещение 0, 2, 4… внутри массива, а не небезопасный адрес объекта Python. `0xFFFFFFFF` означает отсутствие узла; 0 — допустимый адрес. `memoryview` показывает размер и читает/пишет данные без копирования.

`append` и `prepend` меняют только край и связь соседнего узла. `insert_between` меняет связи двух соседей. Внутренняя вставка требует двух действительно соседних адресов в текущем порядке обхода. `check_address` проверяет внешний адрес, но поиск соседства не добавляется к каждой операции: это сделало бы вставку линейной.

Если один адрес — `NOT_FOUND`, вставка идёт к текущему соответствующему краю. Это явно учитывает оригинальный `test_InsertBetween_CanBeChained`: там при вставке в начало второй переданный адрес оказывается хвостом, а ожидаемый результат всё равно требует вставки перед фактической головой. Тест не переписан; поведение с граничным маркером определено явно.

`reverse()` только меняет местами `first` и `last`. XOR симметричен, поэтому переписывать связи не нужно: O(1). Поиск `address(value)` и обход — O(n). Ёмкость буфера удваивается, поэтому добавление имеет амортизированную O(1) стоимость; отдельное увеличение буфера — O(n). Лимит этой учебной реализации — 65536 узлов, начальная ёмкость 8.

## Проверка в Windows

```powershell
python -B run_teacher_windows.py
python -B -m unittest -v test_extra.py
```

`teacher_tests.py` сохранён без изменений из архива преподавателя. Оригинал использует `forbiddenfruit` для добавления `times` к int и POSIX-таймер `timeout_decorator`, который не работает штатно в Windows. Наш загрузчик заменяет синтаксис `.times(...)` обычным циклом и отдельно измеряет исходные четыре ограничения **10 мс**. Все 60 тестовых методов и их утверждения исполняются; лимит не увеличивается молча. Загрузчик возвращает ненулевой код, если любой тест не пройден или медиана пяти измерений превышает 10 мс.

Первый замер на загруженной машине превышал 10 мс. После оптимизации представления списка проверка дала около 6.8 мс append, 8.9 мс insert, 6.6 мс prepend и 2.4 мс reverse. Это измерение конкретного компьютера, не гарантия времени на другой машине; актуальный финальный замер лежит в `../verification/practice-teacher.txt`.

Оригинальный POSIX timeout-декоратор **NOT RUN**. Для отдельной проверки исходного тестового файла на Linux установи его зависимости и запусти:

```text
python -m pip install forbiddenfruit timeout-decorator
python teacher_tests.py
```

6 дополнительных тестов проверяют 1000 случайных операций относительно обычного списка, реальное XOR-хранение, неверные значения, поиск дубликатов после разворота, вставку после разворота и недопустимые адреса.

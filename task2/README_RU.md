## Как получен ответ

1. Прочитаны бинарные байты каждого из 256 файлов архива `task2.zip`.
2. Для каждого вычислен именно **SHA3-256**, представлен 64 строчными шестнадцатеричными символами. SHA-256 и Keccak-256 — другие алгоритмы.
3. Ключ сортировки: произведение `(значение символа в hex + 1)` по всем 64 символам. Например, `0 → 1`, `a → 11`, `f → 16`. Сумма цифр, числовое значение хеша и алфавитная сортировка здесь неправильны.
4. Записи отсортированы по возрастанию этого произведения. Используются целые Python неограниченной точности; все 256 ключей уникальны.
5. Склеены только сами хеши, без имён файлов, пробелов и переносов: 16384 символа. В конец добавлен email в нижнем регистре, тоже без разделителя.
6. SHA3-256 этой UTF-8 строки — окончательный ответ.

## Воспроизведение

В папке `task2`:

```powershell
python solve.py --email YOUR_REGISTRATION_EMAIL --audit audit.json --submission submission.txt
python -B -m unittest -v test_solve.py
```

Внешние Python-пакеты не нужны. `audit.json` содержит SHA-256 самого архива, все промежуточные SHA3-хеши, ключи сортировки и итог.

Независимая реализация `crosscheck.mjs` использует Node `crypto` и `BigInt`. Для повтора распакуй архив в отдельную папку и передай ей путь и email:

```powershell
Expand-Archive -LiteralPath task2.zip -DestinationPath extracted
node crosscheck.mjs extracted YOUR_REGISTRATION_EMAIL
```

14 тестов проверяют расчёт, нормализацию email, сортировку, архив и ошибки. Дополнительно на реальных 256 файлах сопоставлены Python и Node: совпали порядок, промежуточные хеши и окончательный ответ.

## Что изучить для понимания решения

Python: байты и текст, чтение ZIP, hashlib.sha3_256, шестнадцатеричная запись, генераторные выражения, math.prod, sorted с key, точные целые числа, lower и UTF-8. Пойми отличие SHA3-256 от SHA-256 и Keccak. Затем объясни, почему нельзя округлять произведение цифр через float.

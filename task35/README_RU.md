# Task 3.5 — Data Engineering

Задание: загрузить исходные данные о книгах в реляционную БД, посчитать количество книг и среднюю цену в USD по каждому году публикации, сохранить результат во вторую таблицу. Курс по условию: **1 EUR = 1.2 USD**. Средняя цена округляется до центов.

Срок по сообщению от 14 октября: **среда, 21 октября 2026**. Точный час окончания не задан. По общему правилу курса время без оговорки — UTC.

## Почему входной файл обрабатывается именно так

Файл называется `task1_d.json`, но его содержимое — массив Ruby-хешей: `{:id=>..., :title=>...}`. Обычный JSON-парсер его не читает. `read_records()` в `main.py` заменяет только ключи вида `:key=>` вне строк, затем использует безопасный `json.loads`. Текст названий не изменяется. `eval` не используется. Обычный корректный JSON тоже поддерживается.

Все 5003 ID превышают максимальный знаковый 64-битный INTEGER SQLite. Они записаны в поле `id` типа TEXT без потери цифр. Это идентификаторы, их не нужно складывать или усреднять.

В источнике 3465 цен в USD и 1538 цен в EUR. Дубликатов ID и пустых обязательных полей нет. Встречающийся 2026 год оставлен, поскольку он есть в данных и условие не требует его исключать. Несколько одинаковых названий — разные записи книг с разными ID; они не удаляются.

## Как работает решение — простыми словами

1. `main.py` читает файл и проверяет поля каждой книги, цену, валюту и уникальность ID.
2. `Decimal` преобразует EUR в USD по заданному курсу. Например, `€5.99` превращается в `7.188 USD`.
3. В таблицу `books` цена записывается целым числом тысячных долей доллара: `7.188 USD → 7188`. Поэтому двоичная погрешность `float` не участвует в расчётах.
4. Запрос из `summary.sql` объединяет книги одного года (`GROUP BY`), считает их (`COUNT`) и сумму цен (`SUM`). Затем делит сумму на количество и округляет среднее до центов.
5. `INSERT INTO summary ... SELECT ...` сохраняет все итоги в отдельную физическую таблицу. Это не временный вывод и не представление.
6. Скрипт выгружает обе таблицы в CSV и проверяет, что сумма `book_count` равна 5003.

Средняя цена округляется **после** вычисления среднего, правило — `ROUND_HALF_UP` (ровно половина цента округляется вверх). Отдельные цены после конвертации заранее до центов не округляются: это могло бы изменить среднее.

В SQLite поле `average_price` хранит десятичную строку с ровно двумя знаками (например, `48.08`). Такое хранение сохраняет точные центы; тип `DECIMAL` в SQLite сам по себе не гарантирует отсутствие двоичного `float`. Поле цены в исходной таблице остаётся числовым INTEGER и позволяет выполнять точные SQL-расчёты. Валюта итогового столбца — USD.

## Как объяснить SQL

`yearly_totals` даёт одну строку на год: год, количество книг, сумму цен в тысячных USD. `rounded` переводит точное среднее в целые центы. Для положительных чисел формула `floor((sum_mills + 5 * count) / (10 * count))` эквивалентна округлению среднего до ближайшего цента с половиной вверх. В SQLite деление двух INTEGER является целочисленным. `printf` оформляет результат как доллары и две цифры центов. Весь SQL находится в `schema.sql` и `summary.sql`.
